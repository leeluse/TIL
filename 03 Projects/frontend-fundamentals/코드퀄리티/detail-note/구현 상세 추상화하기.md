한 사람이 코드를 읽을 때 동시에 고려할 수 있는 총 맥락의 숫자는 제한되어 있다
내 코드를 읽는 사람들이 코드를 쉽게 읽을 수 있도록 하기 위해 **불필요한 맥락을 추상화**할 수 있다

### 코드 살펴보기: 1
---
`<LoginStartPage />`는 사용자가 로그인되어 있는지 확인한 후 로그인된 경우 홈으로 이동시키고 있다

```tsx
function LoginStartPage() {
	useCheckLogin({
		onChecked: (status) => {
			if(status = "LOGGED_IN") {
				location.href = "/home"
			}
		}
	});
	
	/* ... 로그인 관련 로직 ... */ 
	return <>{/* ... 로그인 관련 컴포넌트 ... */}</>;
}
```


### 코드 개선하기: 1
---
로그인이 되어있는지 확인하고 사용자를 홈으로 이동시키는 로직이 추상화 없이 노출되어 있다

>  **추상화 없이 노출되어 있다는 말이 무엇일까?**
> `useCheckLoing, onChecked, status, "LOGGED_IN"`과 같은 변수가 무슨 역할을 하는 코드인지 모두 읽어야 알 수 있다는 의미이다


사용자가 로그인되어있는지 확인하고 이동하는 로직을 [[HOC(Higher-Order Component)]] 또는 **Wrapper 컴포넌트**로 분리하여 코드를 읽는 사람이 한 번에 알아야 하는 맥락을 줄인다



> **옵션 1) Wrapper 컴포넌트 사용하기**
```tsx
function App() {
	return (
		<AuthGuard>
			<LoginStartPage />
		</AuthGuard>
	)
}

function AuthGuard({ children }) {
	const status = useCheckLoginStatus()
	
	useEffect(() => {
	 if (status === "LOGGED_IN") {
	  location.href = "/home";
	   } 
   }, [status]);
   
   return status !== "LOGGED_IN" ? children : null;
}

function LoginStartPage() {
	 /* ... 로그인 관련 로직 ... */ 
	 
	 return <>{/* ... 로그인 관련 컴포넌트 ... */}</>; 
 }

```


> **옵션 2) HOC 사용하기**
```tsx
function LoginStartPage() {
  /* ... 로그인 관련 로직 ... */

  return <>{/* ... 로그인 관련 컴포넌트 ... */}</>;
}

export default withAuthGuard(LoginStartPage);

// HOC 정의
function withAuthGuard(WrappedComponent) {
  return <AuthGuard {...props} />
}

 export function AuthGuard(props) {
    const status = useCheckLoginStatus();

    useEffect(() => {
      if (status === "LOGGED_IN") {
        location.href = "/home";
      }
    }, [status]);

    return status !== "LOGGED_IN" ? <WrappedComponent {...props} /> : null;
  };
}
```

### 코드 살펴보기: 2
---
`<FriendInvitation />` 컴포넌트는 클릭 시 사용자에게 동의를  받고 초대를 보내는 페이지 컴포넌트이다

- **가독성**: 가독성을 지키려면 코드가 한 번에 갖고 있는 맥락이 적어야 한다
	하나의 컴포넌트가 갖고 있는 맥락이 다양할 경우 컴포넌트의 역할을 한눈에 파악하기 어렵다
	
	`<FriendInvitation /> ` 컴포넌트는 실제 사용자에게 동의를 받을 때 사용하는 로직을 하나의 컴포넌트에 갖고 있다


- **응집도**: 사용자에게 동의를 받는 로직과 실제로 그 로직을 실행하는 로직인 `<Button />` 사이 거리가 멀어서, 로직 실행을 확인하려면 스크롤을 많이 내려야 한다
	그래서 자주 함께 수정되는 코드인 버튼과 클릭 핸들러가 미처 함께 수정되지 못할 수 있다
	

```tsx
function FriendInvitation() {
  const { data } = useQuery(/* 생략.. */);

  // 이외 이 컴포넌트에 필요한 상태 관리, 이벤트 핸들러 및 비동기 작업 로직...

  const handleClick = async () => {
    const canInvite = await overlay.openAsync(({ isOpen, close }) => (
      <ConfirmDialog
        title={`${data.name}님에게 공유해요`}
        cancelButton={
          <ConfirmDialog.CancelButton onClick={() => close(false)}>
            닫기
          </ConfirmDialog.CancelButton>
        }
        confirmButton={
          <ConfirmDialog.ConfirmButton onClick={() => close(true)}>
            확인
          </ConfirmDialog.ConfirmButton>
        }
        /* 중략 */
      />
    ));

    if (canInvite) {
      await sendPush();
    }
  };

  // 이외 이 컴포넌트에 필요한 상태 관리, 이벤트 핸들러 및 비동기 작업 로직...

  return (
    <>
      <Button onClick={handleClick}>초대하기</Button>
      {/* UI를 위한 JSX 마크업... */}
    </>
  );
}
```


### 코드 개선하기: 2
---
사용자에게 동의 받는 로직과 버튼을 `<InviteButton />` 컴포넌트로 추상화했다
==-> 기존 handleClick 함수로 분리되어 있는 로직을 onClick에 바로 넣어주는 방식을 사용==

```tsx
export function FriendInvitation() {
	const { data } = useQuery(...)
	
	// 이외 필요한 상태 관리, 이벤트 핸들러 및 비동기 작업...
	
	return (
		<>
			<InviteButton name={data.name} />
		</>
	)
}

function InviteButton({ name }) {
	return (
	<Button
		onClick={async () => {
	    const canInvite = await overlay.openAsync(({ isOpen, close }) => (
	      <ConfirmDialog
	        title={`${data.name}님에게 공유해요`}
	        cancelButton={
	          <ConfirmDialog.CancelButton onClick={() => close(false)}>
	            닫기
	          </ConfirmDialog.CancelButton>
	        }
	        confirmButton={
	          <ConfirmDialog.ConfirmButton onClick={() => close(true)}>
	            확인
	          </ConfirmDialog.ConfirmButton>
	        }
	        /* 중략 */
	      />
	    ));
	
	    if (canInvite) {
	      await sendPush();
	    }};
	  }>	
		초대하기 </Button>
	)
}
```
