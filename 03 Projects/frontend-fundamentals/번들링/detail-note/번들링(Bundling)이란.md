### 번들링이란?
---
**번들링(Bundling)**은 여러 개의 파일(특히 JS, CSS, 이미지 등 웹 개발에 필요한 리소스 파일들)을 하나로 묶는 몇 개의 파일로 묶는 작업이다
이렇게 묶인 파일을 번들(Bundle)이라고 한다

![[Pasted image 20260916142038.png]]

웹 어플리케이션을 만들다 보면 JS 파일이 수십, 수백 개로 쪼개지게 된다

각각의 파일은 기능 단위로 잘게 나눠지기 깨문에 개발하기는 편하나, 브라우저가 서버로부터 파일의 수만큼 요청을 보내게 되어 네트워크 비용이 커지고 로딩 속도가 느려질 수 있다

번들링은 이러한 문제를 해결하기 위한 방법이다

### 번들링의 목적?
---
1. **요청 수의 감소**
   수십, 수백 개의 파일을 하나로 묶어 브라우저가 요청해야 할 파일 수를 줄여 로딩 속도를 줄인다
2. **캐싱 최적화**
   묶인 파일 하나만 캐시하면 되기에 효율적이다
3. **유지보수성과 배포 효율성**
   개발할 때는 모듈화를 유지하고, 배포할 때는 성능 최적화가 가능하다


### 번들링 과정 살펴 보기
---
번들링의 흐름을 간단하게 이해해 보자

#### 1. 여러 개의 JS 파일이 있다

개발할 때는 기능별로 파일을 잘게 나눠서 관리한다

```
├── index.js
├── utils.js
├── auth.js
└── dashboard.js
```

#### 2. 파일들이 서로 의존하고 있다

예로, `index.js`가 `auth.js`와 `dashboard.js`를 불러오고, `auth.js`는 `utils.js`를 사용하고 있을 수 있다. 즉, 파일 간에 의존성(dependency) 관계가 생긴다


#### 3. 번들러가 파일 관계를 분석한다

번들러는 프로젝트 안의 파일을 스캔하면서 누가 누구를 쓰는지 분석한다
시작 지점(ex: `index.js`) 부터 출발해서 모든 파일을 찾고 [[의존성 그래프]]를 그린다

![[Pasted image 20260916161941.png]]


#### 4. 하나의 파일로 묶는다 (Bundling)

필요한 파일들을 의존성 순서에 맞춰서 하나의 파일로 합친다

```
└── bundle.js
```


#### 5. 번들러가 추가 최적화 작업을 해 준다

- 사용되지 않는 코드는 제거한다 ([[트리셰이킹(Tree Shaking)]])
- 필요한 경우, 여러 개의 작은 번들을 나눈다 ([[코드 스플리팅]])
- 코드에서 공백, 주석을 없애서 크기를 줄인다 (`Minification`)


#### 6. 최종 결과물을 배포한다

최적화된 `bundle.js` 파일을 서버에 올려 사용자는 브라우저로 빠르게 접근 가능하다
