### 웹팩 도입하고 첫 번들 만들기
---
[[웹팩(Webpack)이란]]을 참고하면 웹팩에 대해 간단히 알 수 있다
웹팩이 무엇인지 알았다면 바로 도입해 보자


- 기본 환경 준비하기
	웹팩을 사용하려면 Node.js가 필요하다. 터미널에서 다음 명령어로 Node.js 및 npm이 설치되어 있는지 확인해 보자. Node.js 버전은 22 이상을 추천한다
	
```
$ node -v
# 명령어를 입력했을 때 v22.13.0과 같은 버전명이 보이면 설치된 거예요.

$ npm -v
# 명령어를 입력했을 때 10.9.0과 같은 버전명이 보이면 설치된 거예요.
```

만약 설치되어 있지 않다면, [Node.js 공식 사이트](https://nodejs.org/)에서 다운로드한다

- 프로젝트 초기화하기
	이제 기존 프로젝트 폴더에서 npm을 초기화 해 준다
	터미널에서 `example-project` 폴더로 이동한 후 다음 명령어를 실행하자

```bash
$ cd example-project
$ npm init -y
```

> **-y는 뭔가요?**
> 모든 옵션에 'yes', 즉 기본값으로 생성하겠다는 의미이다

#### 웹팩 설치하기
---
웹팩과 웹팩 CLI를 개발 의존성으로 설치해 보자

```bash
$ npm install --save-dev webpack webpack-cli
```

- `webpack`: 실제 번들링을 수행하는 도구이다
- `webpack-cli`: 터미널에서 webpack 명령어를 쓸 수 있게 해주는 CLI이다
	- CLI: 마우스 클릭 대신 키보드로 텍스트 명령어를 입력해 컴퓨터나 소프트웨어와 소통하는 텍스트 기반 인터페이스 방식

웹팩은 번들링 도구로, 실제 배포되는 코드에서는 필요 없기 때문에 `--save-dev` 옵션을 통해 개발 의존성으로 설치한다


```
added 100 packages, and audited 101 packages in 5s

17 packages are looking for funding
  run `npm fund` for details
```

위처럼 보이면 모든 웹팩 패키지가 설치된 것이다




### 웹팩 설정 파일 만들기
---
이제 `main.js` 파일을 번들링해서 `bundle.js`로 만들어 보자

먼저 프로젝트 루트에 `webpack.config.js` 이름의 파일을 생성하고 다음과 같이 작성해라

- `webpack.config.js`: 이 설정 파일을 보고 웹팩은 `main.js` 파일을 번들링해서 `bundle.js` 파일로 만든다

```js
const path = require("path");

module.exports = {
  entry: "./main.js", // 어떤 파일을 진입점으로 번들링할지
  output: {
    filename: "bundle.js", // 번들로 만들어질 파일 이름
    path: path.resolve(__dirname, "dist") // 번들 파일이 어디에 저장될지
  }
};
```



### 첫 번들 만들기
---
이제 번들을 만들어 볼 것인데, 다음 명령어를 실행하면 빌드가 시작된다

```bash
$ npx webpack
```
- `npx`는 Node.js와 함께 설치된 도구로, 로컬에 설치된 패키지를 실행할 수 있게 해 준다

빌드가 완료되면 `dist` 폴더 안에 `bundle.js` 파일이 생성된다

`/dist/bundle.js` 를 열어보면 우리가 `main.js`에 적었던 코드가 한 줄로 압축되고, 변수명이 `t`, `e`같은 짧은 이름으로 바뀐걸 볼 수 있다
이렇게 웹팩은 추가 설정을 하지 않아도 기본적으로 코드를 최적화 해 준다


```js
document.addEventListener("DOMContentLoaded", function () {
  const t = new Date(),
    e = dateFns.format(t, "MMMM d, yyyy");
  ((document.getElementById("dateDisplay").textContent = e),
    (function () {
      const t = Math.floor(Math.random() * emojis.length),
        e = emojis[t];
      ((document.getElementById("emojiDisplay").textContent = e.icon),
        (document.getElementById("emojiName").textContent = e.name));
    })());
});
```


첫 번째 번들 파일을 만든 것, 축하해요! 🥳

지금까지 만들어진 파일 구조를 살펴 보자

```
example-project/
├── index.html
├── style.css
├── main.js
├── emoji.js
├── package.json # npm init으로 생성됨
├── webpack.config.js # 직접 생성한 웹팩 설정 파일
├── node_modules/ # npm install로 생성된 폴더
├── dist/ # 웹팩이 생성한 폴더
│ └── bundle.js # 웹팩으로 번들링된 파일
└── assets/

```


### package.json에 빌드 스크립트 추가하기
---
이렇게 매번 `npx webpack` 명령어를 실행하는 대신, `package.json` 파일에 스크립트를 추가하면 빌드 명령어를 한 곳에서 관리할 수 있다

나중에 빌드 과정이 복잡해져도 명령어는 간단하게 유지할 수 있어서 작업을 더 일관되고 효율적으로 진행할 수 있다

`package.json` 파일을 열고 `scripts` 부분을 다음과 같이 수정해 보자

```
"scripts": {
  "build": "webpack"
}
```

이제 추가한 명령어로 웹팩 빌드를 실행할 수 있다

```
npm run build
```


### HTML 파일 수정하기
---
마지막으로 HTML 파일이 실제로 `main.js` 대신 웹팩으로 번들링된 `bundle.js` 파일을 사용하도록 변경해 보자

`index.html` 파일을 열고 스크립트 부분을 다음과 같이 수정해라

```html
<!-- emoji.js는 그대로 유지해요 -->
<script src="./emoji.js"></script>

<!-- main.js 대신 번들링된 스크립트를 사용해요 -->
<!-- <script src="./main.js"></script> -->
<script src="./dist/bundle.js"></script>
```

브라우저에서 `index.html`를 확인하면 번들된 스크립트가 잘 작동할 것이다




## 👣 한 걸음 더: 웹팩 모드 설정
---

우리가 웹팩 빌드 명령어를 실행한 터미널 창을 살펴보면 다음과 같은 경고가 있다

```bash
WARNING in configuration
The 'mode' option has not been set, webpack will fallback to 'production' for this value.
Set 'mode' option to 'development' or 'production' to enable defaults for each environment.
You can also set it to 'none' to disable any default behavior.
```

이 경고는 우리가 웹팩 설정 파일에 `mode`를 추가하지 않아서, 웹팩이 기본값인 프로덕션(`production`) 모드로 빌드했고 말해 준다

> **웹팩은 크게 세 가지 모드를 지원**
>  `mode`를 명시하면 개발과 배포 환경에 맞는 기본 설정이 자동으로 적용돼서, 경고도 사라지고 환경에 맞는 최적화도 더 잘 이뤄진다

- `development`: 디버깅이 쉬운 환경을 제공한다. 소스맵이 기본으로 포함되고, 최소한의 압축(공백 제거, 변수명 단순화 등)만 적용된다
- `production`: 파일 크기를 줄이는 데 집중한다. 코드 압축, 사용하지 않는 코드 제거(tree shaking) 같은 고급 최적화가 자동으로 적용된다
- `none`: 아무 최적화도 적용하지 않는다. 설정을 전부 직접 커스터마이징하고 싶을 때 사용한다

우리는 현재 개발환경에서만 작업하고 있으니 개발 모드로 설정해 주자

```js
// webpack.config.js
module.exports = {
  mode: "development"
  // 기존과 동일
};
```

다시 빌드를 해보면 경고 문장이 사라지는 걸 볼 수 있다
